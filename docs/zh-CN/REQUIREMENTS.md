# Amazon Listing 改写 Skill 产品需求文档

[项目首页](README.md) · [English](../en/REQUIREMENTS.md) · [完整示例](EXAMPLES.md)

## 产品目标

帮助亚马逊运营和 Listing 审核人员用可核对的依据判断该先改哪里，写出候选稿，再检验买家能否从新文案找到答案。支持从各类目的单个字段开始，规则按实际站点和类目核验。

## 当前满足哪些需求

| 运营遇到的问题 | 当前提供的功能 | 交付结果 |
| --- | --- | --- |
| 我只有 ASIN，想先确认查到的是哪个型号。 | **商品识别**按站点核对所选子体。 | 身份卡，含品牌、型号、变体、来源、日期和已读字段。 |
| 我只有标题和一条五点，想知道最值得改哪里。 | **Listing 评分**评估提供或已读取的原文。 | 逐字段分数、计分范围、原文短引和按优先级排序的意见。 |
| Alexa 的回答把某个功能的使用条件说漏了。 | **问句导向改写**先拆条件，再核对功能证据。 | 候选文案、修改理由、字段长度检查和同题复评。 |
| 我想看竞品怎么解决同一个购买问题。 | **竞品功能调研**逐款核对功能和页面表述。 | 含型号、功能、条件、日期、原文和可回答性分的对照表。 |
| 我有 Alexa 实测记录或旧版 Listing。 | **证据复核与前后比较**使用实测资料或工作台导出。 | 带来源的答复、引用和商品卡记录，以及口径可比的复评结果。 |

## 输入与证据要求

| 输入 | 处理要求 |
| --- | --- |
| **Amazon 商品链接** | 从零售域名确定站点并识别 ASIN。核对页面选中的子变体，再引用该变体的功能。 |
| **裸 ASIN** | 优先沿用用户指定或当前对话的站点。未指定时从美国站开始并标记默认值。有联网能力时先查询，再提供三个选项。 |
| **Listing 或已保存资料** | 支持一条原文或完整 Listing，包括粘贴文案、截图、HTML、说明书和工作台导出 Markdown。保留来源与适用日期。 |
| **Oxylabs 类目 CSV** | 将 ASIN、标题、链接、图片链接和价格当作候选索引，按站点和子 ASIN 去重。用对应详情的证据做内容评分和功能对比。 |
| **卖家规则或 Alexa 记录** | 使用适用站点和类目规则，或用户的实际测试记录。保留问句原文、发生时间和条件。 |

每个字段记录为 **已取得已确认、已取得待核实、未取得、已确认不存在、当前不适用**。归档同时记录原采集时间和本次读取时间。同型号的说明书或用户已确认的实测可用于核实产品事实。评论、Q&A 和竞品可用来发现买家关心的问题。

遇到验证、登录要求或拒绝访问时停止该次网页读取，接着用授权资料或用户提供的原文。目标 ASIN 与页面选中变体冲突时，展示两个标识，等用户确认后再评对应变体。

## 功能要求

### Listing 评分

- 对有原文的字段按「直接回答、具体性、事实与边界、清晰与去重」评分，每项 25 分。
- 总分取已评字段的平均值，给出计分范围。缺失字段未评分，前后变化仅比较共同评分字段。
- 诊断要引用原文并指到具体字段。已证实的事实错误或规则冲突为 P0，核心问题没有答清为 P1，可读性优化为 P2。
- 用户要求时，可独立记录购物车、配送等可见状态，注明站点、观察时间和条件。

### Alexa 问句导向改写

- 把买家问题拆成可核对的条件，找出对应功能、操作、结果和限制。
- 只改指定字段。每个关键改动对应核实过的事实，待核验项放在候选稿之外。文案使用目标站点语言。
- 给出原文、候选稿、依据、长度结果，并用同一组问句复评。证据不足时保留待核状态。
- AI 推拟问句标为候选。提供 Alexa 实测时，记录入口、语言、会话条件、答复、引用、目标 ASIN 和广告标识。在可判断轮次上计算回答正确率并展示样本量，商品卡出现情况单独统计。

### 竞品功能调研

- 优先使用用户指定的竞品。否则寻找 2–5 个有证据的同站点替代品，报告实际样本数和纳入原因。
- 逐款列功能状态、规格或操作、适用条件、原文和来源。资料不足的能力标为未知。
- 对同一组问题按 0–2 分评估页面可回答性。准确明确得 2 分，回答一部分得 1 分，在可评原文里缺答案或与已核实事实冲突得 0 分。相关资料未取得时标 N/A。汇总百分比使用各款共同可评分题目。
- 标注问句来自买家评论、录入的 Alexa 实测或 AI 推拟。频率有来源才填写。

### 字段长度验证

- 核对站点、类目、字段、生效时间和计量单位。逐条检查五点，逐文本框检查 A+。
- 输出实际长度和已核实的上限，支持含上限、严格小于和 UTF-8 字节等口径。
- 上限还未确认时给出实测长度及待核状态。最终文案由运营在 Seller Central 核对和发布。

## 验收清单

| 测试场景 | 预期结果 |
| --- | --- |
| 只给 ASIN，能读到详情页 | 核对实际站点和子变体，标出证据和可用字段，给出三个功能选择。 |
| 详情页受限或无法读取 | 说明成功取得的来源和缺失字段，按需要提示补同变体的原文或导出。 |
| 只提供标题和一条五点，A+ 缺失 | 现有文案能评分，A+ 显示未评分。 |
| 标题 76 字符，已核实该上限为 75 | 原文提示超限，候选稿重新计数。上限含 75 时，75 字符通过。 |
| 示例中 Search Terms 要求严格小于 250 字节 | 249 UTF-8 字节通过，250 字节超限。实际应用前核对该站点规则。 |
| 首次用 App 设置，之后可关 App 使用 | 文案保留首次设置与已保存食物条件。是否需要蓝牙或网络以证据为准。 |
| 竞品明确说自己不具备该功能 | 功能状态记录为不支持，页面因答得明确仍可拿到该题满分。 |
| 没有 Alexa 实测资料 | 输出候选问句以及文案可回答性结果。 |

## 运行范围与后续方向

Skill 通过所用 AI 运行，使用用户提供的资料及当前可用的授权商品工具。审核通过的候选稿由运营在 Seller Central 发布。需要保存快照、版本和复评结果时，可配合 Listing 工作台。

后续可加入类目规则库、结构化导入实测记录，以及关联上线版本与 Alexa 实测、Amazon 内容实验结果。落地取决于数据权限和测试条件是否可比。[Listing 工作台](https://github.com/kurikiwoods-coder/amazon-listing-workbench)
